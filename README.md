# AIport — продающий сайт

Статический сайт на Astro 5 и TypeScript по ТЗ «продающий сайт». Основная аудитория — собственники магазинов на маркетплейсах. Дополнительные лендинги — для малого бизнеса и частных лиц.

## Запуск

Нужны Node.js 24 и npm. Необходимые для сайта шрифты и иллюстрации уже находятся в репозитории. Сервер, база данных и API-ключи для просмотра сайта не нужны.

```sh
npm ci
npm run dev
```

Команды выполняются из корня репозитория. Сервер разработки слушает порт 4321 на всех интерфейсах. Каждая облачная задача уже изолирована: используйте существующий checkout, создавать Git worktree не нужно.

Для проверки собранной версии:

```sh
npm run check
npm test
npm run build
npm run test:site
npm run preview
```

`npm run test:e2e` запускает Playwright и временный сервер собранного сайта. В этой облачной среде используется `/usr/bin/chromium`. На другой машине укажите `CHROMIUM_PATH` или установите Chromium. В тестах проверяются фильтры, цены, меню, формы, API-ответы, согласие на аналитику, ref/UTM и доступность основных типов страниц через axe. Настоящие платформенные запросы в интеграционных тестах заменены тестовыми ответами.

`npm run assets` пересоздаёт WebP-иллюстрации и общую PNG-картинку Open Graph. `npm run format` форматирует исходники.

## Что реализовано

- Общая шапка, мобильное меню, подвал, 404 с поиском.
- Три лендинга: `/`, `/biznes/`, `/dlya-sebya/`.
- Главная с макетом диалога ИИ, сервисами, тремя шагами, шестью вопросами, блоками собственника и безопасности, тарифом, FAQ и финальным призывом.
- Каталог `/katalog/`: 16 сервисов, поиск, категории, аудитории и статус. Фильтры сохраняются в query string.
- Отдельные страницы всех сервисов; Markdown-инструкции для 10 доступных в локальном каталоге подключений.
- Инструкции для 8 ИИ-клиентов.
- Тарифы 890 ₽/месяц и 7 476 ₽/год с переключением периода и передачей `plan`.
- Безопасность, 15 FAQ, партнёрская программа и юридические шаблоны.
- Блог: три статьи, оглавление, похожие статьи, RSS.
- Экспорт 33 статей базы знаний в `/kb.json`.
- Canonical, уникальные title/description, Open Graph, JSON-LD, robots и sitemap.
- Cookie-баннер, Метрика после согласия, цели `cta_click`, `vote_service`, `chat_open`.
- Cookie `ref` на 60 дней и `utm` первого касания на 30 дней; общий домен при совпадении с настроенным доменом сайта.
- API каталога при сборке, резервная локальная копия, формы голосования и отложенный виджет поддержки.
- GitHub Actions: push в `main`, ручной запуск, ежедневная сборка и `repository_dispatch` типа `catalog-updated`.

## Настройки

Для локальной конфигурации скопируйте `.env.example` в `.env`. В GitHub Actions добавьте соответствующие **Repository variables**. Это публичные параметры, не секреты: не записывайте сюда токены, пароли и API-ключи пользователей.

| Переменная                   | Назначение                                                   |
| ---------------------------- | ------------------------------------------------------------ |
| `PUBLIC_BRAND`               | Текстовый бренд, по умолчанию AIport                         |
| `PUBLIC_SITE_URL`            | Полный адрес сайта, например `https://ваш-домен.ru`          |
| `PUBLIC_APP_URL`             | Полный адрес платформы, например `https://app.ваш-домен.ru`  |
| `PUBLIC_SUPPORT_EMAIL`       | Email поддержки                                              |
| `PUBLIC_YM_ID`               | Числовой ID Яндекс Метрики                                   |
| `PUBLIC_LEGAL_NAME`          | ФИО ИП / оператор                                            |
| `PUBLIC_LEGAL_INN`           | ИНН                                                          |
| `PUBLIC_LEGAL_OGRNIP`        | ОГРНИП                                                       |
| `PUBLIC_YANDEX_VERIFICATION` | Код подтверждения Яндекс Вебмастера                          |
| `PUBLIC_SECURITY_VERIFIED`   | `true` только после проверки заявленных мер защиты платформы |

Настройки считываются при сборке. После изменения нужен новый `npm run build` или перезапуск dev-сервера.

Без `PUBLIC_APP_URL` кнопки кабинета ведут на локальную страницу с объяснением, а форма прямо сообщает, что email не отправлен и не сохранён. Не симулируются ни успешные регистрации, ни голосования. Без `PUBLIC_YM_ID` Метрика вообще не загружается. Указанные в локальном каталоге статусы — исходные данные ТЗ, не результаты проверки реальных интеграций.

## Контракт с платформой

- Регистрация: `/signup?plan=month` или `year`; вход: `/login`; подключение: `/connect/{service_id}`.
- `GET /api/public/catalog`: при ошибке сети, HTTP или схемы используется `src/data/catalog.json`. Последний снимок для сборки сохраняется в игнорируемом `.astro/catalog.json`; сам отслеживаемый JSON не изменяется.
- `POST /api/public/votes`: `{service_id, email}`; успех — только HTTP 200/201. Ошибки и rate limit видны пользователю, email в браузере не сохраняется.
- Для произвольного предложения сервису передаётся `service_id: "custom:Название"`. **Обработку этого соглашения нужно согласовать с платформой**, поскольку ТЗ не задаёт отдельное поле для свободного названия. До этого не обещайте доставку таких предложений.
- Виджет: `/widget/chat.js`, `data-source="site"`, загрузка после взаимодействия или через 3 секунды. Кнопки инструкций используют `window.supportChat.open()`. Без готового виджета открывается локальная помощь и email, если он указан.
- `/kb.json`: `version`, `updated_at`, `articles` с `title`, `description`, Markdown-текстом `text`, абсолютными `url` и `images`, `updated`, опциональными `service_id`/`client_id`.
- CORS каталога и голосов, дедупликация, серверный лимит 5 запросов в минуту и привязка `ref` к аккаунту — ответственность платформы. Реальный сервер в этом репозитории не создаётся.

Контрактные адреса и поля сохранены. Окончательная проверка регистрации, оплаты, шифрования, чтения API и передачи реферального кода потребует работающей платформы.

## Контент и оформление

- `src/styles/tokens.css` — общие токены для сайта и будущего кабинета.
- `src/data/catalog.json` — резервный каталог и тарифы.
- `content/help/{services,ai,faq}/` — коллекции базы знаний.
- `content/blog/` — статьи.
- `public/img/help/` — поясняющие схемы. Они подписаны как схемы, не скриншоты.
- `public/img/blog/` — WebP-иллюстрации; `public/img/og.png` — общее превью.
- `public/fonts/` — Onest из Fontsource, лицензия OFL рядом. Шрифт используется локально из-за недоступности Google Fonts в облачной среде; `font-display: swap` и preload сохранены.

У сервисов без `icon_url` показаны аккуратные текстовые обозначения. Для финального запуска подставьте официальные разрешённые логотипы через `icon_url`. Не используются вымышленные скриншоты кабинетов или ключи.

## Публикация на GitHub Pages

Домен владелец добавит позже. Для первого деплоя используется GitHub Pages по адресу `https://100pasha.github.io/aiport_site/`. По умолчанию сайт использует технический адрес `https://aiport.example` только для локальной подготовки; он не предназначен для публикации.

1. После появления коммита в `main` включите GitHub Pages → Source: **GitHub Actions**.
2. Если домен ещё не выбран, оставьте `PUBLIC_SITE_URL` пустым в Repository variables. Для собственного домена укажите его полный HTTPS-адрес. Без собственного домена workflow использует `https://100pasha.github.io/aiport_site/`. Все ссылки, изображения, шрифты, RSS и база знаний учитывают этот путь; при указании собственного домена сборка автоматически переходит в его корень.
3. Настройте DNS и Custom domain в GitHub Pages. Сборка сама создаёт `dist/CNAME` и `.nojekyll`.
4. Включите **Enforce HTTPS** после выпуска сертификата GitHub.
5. Укажите адрес платформы, поддержку, реквизиты и счётчик; проверьте окончательные документы.
6. Запустите workflow и подтвердите сайт в Яндекс Вебмастере. Sitemap: `/sitemap.xml` (также доступен Astro `/sitemap-index.xml`).

Настройка DNS, включение HTTPS, отправка sitemap в Вебмастер и публикация требуют действий в аккаунтах владельца. В рамках этой работы внешняя публикация не выполнялась.

## Что требуется перед публичным запуском

- Домен, адрес работающей платформы, контакт поддержки и реквизиты ИП.
- Проверка и утверждение юридических шаблонов; в них намеренно видна отметка предварительной редакции.
- Проверка реальных разрешений всех API: OAuth и токен сами по себе не гарантируют права только на чтение.
- Реальные скриншоты из тестовых кабинетов со скрытыми секретами и проверка инструкций, особенно текущих тарифов и интерфейса ChatGPT.
- Подтверждение шифрования ключей, расположения сервера и исключения персональных данных. Не устанавливайте флаг проверки до фактической проверки.
- Проверка интеграции с платформой, голосов, виджета и оплаты на её тестовом контуре.

## Проверки в этой среде

Итоговый прогон: Astro/TypeScript — без ошибок и предупреждений; три Node-теста и 18 браузерных тестов прошли. Проверены восемь типов страниц через axe. Lighthouse на главной в мобильном режиме: Performance 100, Accessibility 100, Best Practices 100, SEO 100. Это локальные лабораторные результаты; после подключения аналитики, чата и реального домена измерения нужно повторить.

Отчёты, трассы браузера и снимки экрана находятся в игнорируемой папке `artifacts/`, `test-results/` и `playwright-report/`. Они не попадают в публикуемый сайт.
